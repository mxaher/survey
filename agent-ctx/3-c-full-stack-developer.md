## Key UX decisions
- **Key-based form remounting**: both editor views (QuestionEditorView, ExecutiveEditorView) are split into a parent data-fetcher + child form component keyed by `id`. The child initializes its state from `initial` props via `useState(initializer)`. This avoids the `react-hooks/set-state-in-effect` lint error (which is enabled by default in this project's eslint config) and is the React-recommended pattern for hydrating form state from server data.
- **Side-effects in onChange handlers**: instead of using `useEffect` to clear code-error-on-code-change or prefill-options-on-type-change, I moved those into the relevant `onChange`/`onValueChange` handlers. This is the natural React way to react to user input.
- **DnD reorder with optimistic cache update**: when the user drops a sortable item, I update the TanStack Query cache immediately via `qc.setQueryData(...)` so the UI reflects the new order without waiting for the network. The reorder POST fires in the background and silently invalidates the query on success. On error, the optimistic update is reverted by the invalidation refetch.
- **ActionButton for lifecycle actions**: every delete / activate / deactivate action uses the shared `ActionButton` (which already implements confirm-with-window.confirm + toast + invalidateQueries + loading state). For the multi-select "add to campaign" case in the QuestionsTab, I used a plain Button because the ActionButton pattern (single mutation per click) doesn't fit; instead the plain Button calls `assignMutation.mutate(Array.from(selectedIds))`.
- **Safe dynamic imports for Task 3-b's components**: `CampaignDetailHeader` and `CampaignEditorView` are loaded via `next/dynamic` with both a `loading` fallback and a `.catch()` fallback. If 3-b's files exist, they're loaded; if not, inline fallback components render. The `.then()` also handles the case where the module loads but the named export is undefined (`m.CampaignDetailHeader ?? FallbackHeader`). This means my CampaignDetailView compiles + runs whether or not 3-b has finished.
- **Preview tab is GET-only**: the PreviewTab uses `useQuery` against `/api/admin/campaigns/[id]/preview`. No mutations are wired up. The banner `MESSAGES.previewBanner` is shown at the top so the admin knows nothing will be saved.
- **Readiness tab gated on `alreadyActive`**: when status is active/closed/archived, the "فتح الحملة" button is replaced with an Alert explaining the campaign is already activated/closed/archived. The button is also disabled when `r.ready === false`.
